## Evidence gates (how each idea is proven)

- **Comprehension gate wired into the evidence checker (no editing without a model)** — cpp_evidence_check.py --profile comprehension exits non-zero on a report with blank/uncited comprehension fields and exits zero only when each field cites a verifiable anchor; demonstrated by a pass/fail fixture pair committed under the script's test path and by running it against a real filled report.
- **Add port/modernize/rearchitect profiles to cpp_evidence_check.py + gate report rows + Task Router/Reference Map entries** — Construct a deliberately incomplete gate report (port profile, differential-oracle field left as placeholder) and confirm cpp_evidence_check.py --profile port --require-differential-oracle EXITS NON-ZERO naming the missing field; then fill it and confirm PASS. Confirm validate_skill_contract.py still PASSes with the three new references present, and that the Task Router/Reference Map rows resolve to existing files (no broken-link failures).
- **Cross-link the documentation sibling skills via the existing Repeat-Skill Extraction table** — On a real repo, the agent generates a README, then runs de-slopify over it and shows a diff removing at least the standard AI tells (no 'seamless/robust/leverage/in today's world', no em-dash-marketing, no empty 'comprehensive solution' framing); proves the README still passes readme-writing's structure check (required sections present) and that the changelog produced by changelog-md-workmanship reconstructs the real tag history (each version entry maps to an actual git tag/commit range).
- **UNKNOWN-DOMAIN.md derivation template: how to build a pack on the spot** — Run the template against a repo whose domain is deliberately not packaged (e.g. an audio DSP codec or a database storage engine). The agent must emit a complete ad-hoc pack and then execute at least its top two derived gates with real output, and a reviewer confirms the derived refusal conditions actually map to that repo's real trust boundary rather than generic boilerplate.
- **Scope-to-profile derivation: make cpp_evidence_check.py read Change Scope and require the matching profiles** — On a real repo, run the existing checker on a report with 'Parser...: yes' and only --profile basic and capture exit 0 (current behavior); then run with --derive-profiles and capture a non-zero exit naming the missing parser profile. Commit both transcripts. A second positive case: a fully-scoped report with all matching --profile flags must still PASS under --derive-profiles.
- **Constrain Change Scope vocabulary to {yes,no} and reject free-text answers** — Run the checker on a report containing 'Public API/ABI touched: maybe' and capture the new FAIL line 'Change Scope: Public API/ABI touched must be yes or no'. Then flip it to 'yes' and 'no' on two copies and capture PASS for both. Include before/after transcripts proving 'maybe' was previously accepted.
- **COMPREHENSION.md reference + cpp_comprehension_map.sh: a staged mental-model-first workflow** — Run cpp_comprehension_map.sh on a never-seen OSS repo (e.g. one not in the study corpus); the agent must produce a filled comprehension block whose claimed entry point is confirmed by grepping the binary's symbol table / the build target's link line, and whose module->target table is cross-checked against `cmake --graphviz` or `ninja -t graph` output with zero phantom targets.
- **Domain-intent reconstruction checklist (no-docs onboarding)** — On a stripped repo with README deleted, the agent states a domain hypothesis with at least 3 cited signals (file:line or symbol), then proves it by either feeding a known-format input through the entry point and matching expected output, or by pointing to a standard/RFC identifier found in-tree that names the format.
- **PORTING-WORKFLOW.md: executable port transform loop with behavior-oracle differential gate** — On a real repo with a portable C/C++ target, run the origin build, capture the oracle corpus, then cross-build for a second target (e.g. aarch64 via the project cross file or qemu-user) and run the same corpus; the gate passes only when the differential diff is empty or every divergence is logged as intentional with a recipe applied, AND cpp_evidence_check.py --profile port passes with a filled differential-oracle field naming origin triple, target triple, emulator/hardware path, and corpus size.
- **MODERNIZE-WORKFLOW.md: standard-raise + clang-tidy transform catalog with per-transform isomorphism and ABI gates** — On a real pre-C++11 or C++11 repo, raise the standard one step, build warning-clean, then apply a single clang-tidy modernize check (e.g. modernize-use-nullptr) with --fix on the touched files; gate passes only when the test suite + golden outputs are byte-identical to baseline, the ABI snapshot (cpp_abi_snapshot.sh) shows no unintended symbol/layout delta for any public boundary, and cpp_evidence_check.py --profile modernize passes with the per-transform check name and isomorphism field filled.
- **REMEDIATION-RECIPES.md: buggy→corrected fix cookbook** — On a real repo, agent runs cpp_risk_scan.sh, picks one real hit (e.g. a strcpy or naked malloc), applies the matching recipe, and proves the fix with: (a) a regression test that fails pre-fix and passes post-fix, and (b) the recipe-named gate green (ASan+UBSan clean for the bounded-copy/overflow recipes, TSan for false-sharing, abidiff clean for RAII-at-boundary). Recipe is only 'working' if the cited gate command output is pasted in the gate report.
- **cpp_perf_proof.py: parse real benchmark numbers, not just marker strings** — Agent points the checker at two real JSON benchmark exports from a repo: a regression case (after slower) must FAIL the gate, and a genuine win (after faster beyond noise) must PASS. Self-test ships two fixture JSON pairs (one win, one regression, one within-noise) the checker classifies correctly; agent demonstrates by running the checker on a live hyperfine export from the target repo and pasting the verdict.
- **ACCRETIVE-BACKLOG.md + cpp_backlog.sh: derive an improvement backlog from inventory and risk-scan output** — On a real C/C++ repo (e.g. a vendored open-source library checkout), run cpp_inventory.sh and cpp_risk_scan.sh, feed both to cpp_backlog.sh, and prove every emitted backlog row cites a concrete evidence anchor (file:line from the risk scan or a specific inventory key); then prove the engine is not hallucinating by injecting a known gap (delete the fuzz harness / add a strcpy) and showing the corresponding row appears, and removing it (add the harness) and showing the row disappears. Backlog must be reproducible: two runs on the same tree byte-match.
- **IDEA-GATE.md + cpp_idea_check.py: an evidence gate designed FOR proposals, not implementations** — Author two Idea Cards against a real repo: one well-formed (real profile-backed problem, prior-art link, kill criterion) and one deliberately weak (problem-evidence = 'feels slow', no prior-art, no kill criterion). Prove cpp_idea_check.py passes the first and rejects the second with a field-level reason for each missing/placeholder item, exactly as cpp_evidence_check.py rejects unfilled gates. Prove the placeholder set (e.g. 'feels slow', 'tbd', 'maybe') is caught by the same normalize/is_placeholder logic. Register both the script and reference in validate_skill_contract.py and show the contract validator still passes.
- **Generalize the two Opportunity Matrices into a single domain-agnostic Idea Scoring rubric with an upside-weighted score** — Take a real repo's backlog from cpp_backlog.sh, score every row with both the accretive score and the radical expected-value score, and prove the two scorers rank the SAME candidate differently (a high-upside/low-confidence item that the perf-style score would reject but the radical scorer surfaces). Show the portfolio rule fires: the ranked output contains at least one kind=radical item even when accretive items dominate by raw score. Demonstrate determinism: identical backlog input yields identical ranking.
- **DOCUMENTATION-AUTHORING.md reference + Task Router/Reference Map wiring** — On a real C/C++ repo (e.g. a small CMake library), an agent follows the reference to generate README.md + ARCHITECTURE.md + a Doxygen config and proves: README install commands actually configure/build/install the project (copy-paste the commands, show exit 0); every public symbol in the installed headers appears in the generated API reference (diff `nm -D --defined-only` exported names against Doxygen XML index, zero undocumented public symbols); the docs-site builds with zero Doxygen/Sphinx warnings (`-W` fail-on-warning) and at least one usage example in the docs compiles and runs.
